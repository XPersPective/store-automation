# ADR-004 — Native CLI teams with one authority and evidence-gated economical routing
Status: ACCEPTED
Date: 2026-10-12

## Context
User asks architecture-first combined requirement analysis, repeated independent critique/revision, mandatory native CLI delegation/discovery, lowest sufficient model including director own cheaper or stronger models, quota/reset and equivalent incomplete-work handoff, visible GUI intervention/artifacts. Phone setup secondary. Existing2.2 runtime has useful metadata/ownership/HTTP/Brain components but no universal account/control/visual proof.

## Evidence
Actual bounded discovery13 CLI entrypoints, MiMo7 model IDs, MCode/Kimi ACP configOptions model/effort metadata. Independent official native Sol/high -> Astra/high -> fresh Sol/high critiques; last typed report blockers=[] and parent-checked source hash. See docs/evidence/architecture-critique-20261012.md; no raw private files distributed.

## Decision
Keep Project Brain and Store Automation separate with one project-owned plan, existing chat director and one managed assignment/dispatch/acceptance authority. No combined skill, third generic skill, new plan DB or mandatory inference proxy. Full target and request/acceptance matrix live only in docs/architecture-cli-team.md.

Native adapters own documented CLI metadata/account/billing/quota/permission/start/observe/stop/report/intervention, advertise unsupported controls honestly. Native host paths enter same authority. Deterministic discovery and quota observer; scoped resume summaries and least-sufficient evidence-qualified model. Risk/complexity separate; controlled representative CALIBRATING prevents model-enrollment deadlock.

Account shared-bucket atomic admission, soft reserve, fresh reset measurement and generation-bound immutable attempts. Durable contained spawn handshake before mutation; unsupported exact write/containment means read-only patch. Scoped controller/UI/report capabilities, sanitized worker env; strict same-user isolation needs separate OS identity, no prose guarantee. Actual native rendering/message/reconcile and artifact gates remain required.

## Rejected choices and criticism
Merge makes generic Brain provider/app dependent; third skill has no second consumer yet; OmniRouter proxy does not establish native permission/account semantics. Critic suggestion to put leases/journal in Brain rejected: violates single plan/state separation; ignored control records and references suffice. Infinite review/benchmark loops are not quality: three focused iterations closed target contradictions; runtime must now prove acceptance.

## Impact
Extends ADR003 with concrete target gates, retains app-sequential/one-writer boundaries and existing helpers. PB027 scope narrowed to pending tested dispatch/metadata corrections. PB031-PB036 enumerate implementation; PB028 console depends on native handoff/transports; PB029 phone setup deferred, distribution only after runtime/visual acceptance. PB005/PB019/PB023 keep external provider/native proof limits; PB020 older fixed AGY preference does not govern new all-provider task-suitable target. PB002/PB011/PB015 and weeklyPB026 retain their unrelated existing scopes. All18 open tasks audited for keep/edit; none silently deleted or marked implementation complete.
