# ADR-003 — Dynamic catalogue and task-dependent specialist teams
Status: ACCEPTED
Date: 2026-10-11

## Context
Latest user requires automatic all-installed/free/API discovery, coordinator plus worker quota checks, complete product intake and more than three agents in a polished console. Prior three-pane/Codex-only assumptions and AGY-only catalogue cannot meet this scope. Audits traced bootstrap's missing platform forwarding, watcher three-session ceiling and metadata-only subscription adapters.

## Decision
Reuse canonical per-project Brain, installed native clients and Windows Terminal. Director/implementation/fresh-review remain responsibilities; team count follows task needs, with one app writer. Skill automatically discovers fresh metadata and evaluates eligible task capability; existing wrapper exposes unsupported interfaces honestly. Reuse Skills Manager's dynamic registry instead of expanding a second complete host list. Public free API models remain discovery candidates until approved actual access/permissions/quota/quality proof.

Keep existing references as single source for intake/stages/routing/handoff. Templates remain external compatible Git refs; generator shared source forwards selected targets. No new orchestrator database, terminal, dependency or credential handling.

## Evidence and limits
Root machine checks, independent traversal/forwarding/realistic-intake reviews, generated Windows-only22tests and core163tests validate implemented changes. Unit tests and catalogue listing do not prove native multi-provider conversation, automatic intervention relay or continuous account telemetry. PB-023 retains those gates; PB-005 retains account/model access, PB-002 real stores/iOS. No production-ready claim before actual evidence.

## Impact
PB-021/PB-022 implement skill/runtime revision; PB-020 must follow current all-provider policy rather than fixed AGY/team preference. PB-019 remains optional Codex-specific attachment evidence. Other unfinished app/store/isolation tasks keep their current scope.
