---
name: app-factory
description: Sequential Flutter App Factory using validated contracts, existing napp template, one Project Brain and evidence gates
---

Load store-automation for the current product-delivery, routing and architecture-review
protocol. Read only references needed for this task. Resolve `<runtime>` as the third
parent of this skill's directory; `<cli>` is `python "<runtime>/tool/factory.py"`.
Run from the selected project root, never assume installed tools live in that project.

1. Boot the selected project's Brain with `<cli> brain boot`. Before investigation,
   run `<cli> providers --catalogue`: create only if absent, reuse otherwise with
   fresh supported account gates. Full `providers --scan` only on explicit user rescan.
   Assess task risk, route the least sufficient model including director alternatives,
   and announce task/role/provider/model/effort/reason/budget. Verify real Git diff.
2. Extract app spec: purpose/platform/locales/package/quality/device budget. Always
   offer completely free mode. Production monetization requires user decision.
3. Pick local napp starter; record source commit and kit ref. Reuse its generator.
4. Select backend only for actual capabilities. `<runtime>/docs/services.md` provides
   official source links; verify free quota/terms/region on the selection date and
   save ADR. No automatic provider migration or paid escalation.
5. PB new creates the canonical task. Write complete JSON contract using
   `<runtime>/contracts/delegation-smoke.json` as the full format example. Run `contract` check.
6. Supported Codex `<cli> run` provides read-only source snapshots. Write work needs
   verified host scope or a reviewed patch applied by the director; no generic native
   write containment is claimed. Other account/quality-unverified inference routes
   are blocked. Native host tasks must meet the same catalogue/account/risk/announcement
   gates. Dispatch one bounded factory-worker, then
   deterministic test/build evidence; never consider worker text completion.
7. Dispatch fresh factory-reviewer after machine checks. Missing screenshots,
   store verifier, account or Xcode is BLOCKED. Use `gate` to reject stale evidence.
8. Supervisor accepts only verified work; Brain reconcile/validate/checkpoint.
9. On quota/timeout/crash: checkpoint, boot, reuse catalogue and refresh account gates,
   verify partial source/tests. Replace only after owned workers stop, with an approved
   equally capable route; otherwise await access/reset. Continue first unchecked acceptance.
10. Release preparation loads factory-release and the product delivery protocol.
    Production requires exact selected app/account/action authorization; reuse it if present.

Minimum UI contract: light/dark, phone/tablet/landscape, 48dp targets, text scale
1.3/2, 4.5:1 contrast, loading/empty/error, screen-reader and actual screenshots.
Code contract: fatal analysis, meaningful tests, no scope creep, source-linked build.
Every result names failure class and next action. Never fabricate evidence.
