# Store Automation

## Single entry and visible work

The user invokes **only `$store-automation`**, or selects `store-automation` in the host's skill/slash menu. Load Project Brain internally; never require two manual invocations. Project Brain owns memory and acceptance; this skill owns CLI discovery, task distribution, native execution and visibility. Keep these separate reusable skills with this single entry.

After Brain boot, perform automatic installed-client/model/effort/account discovery before routing. Delegate bounded repository rescans, evidence collection and routine investigation to the lowest sufficient verified model; deterministic machine checks need no model. The current director's own cheaper CLI models participate in the same pool. High-risk tasks preserve a strong quality floor even when their diff is small. A lower-capability director delegates architecture to a stronger verified specialist when necessary. Record task, risk, selection reason, soft token budget and measured usage for every attempt. Never equate model presence, an ACK or a completed process with accepted work.

When starting from an existing GUI conversation, keep that conversation as director and start `<cli> console --open-browser --contract contracts/<task>.json --prompt-file contracts/<task>.txt` for the native workers. The responsive authenticated browser panel displays actual CLI tasks, models/effort, quota and public messages, and supports native message/interrupt. Open the provided local URL in a supported host browser when possible; default browser is the verified fallback. Do not claim a Codex terminal sidebar attachment unless that host reports one. The console is a real native CLI transport, not a simulated task list. Additional contracted tasks may use repeated flags; shared account admission serializes outstanding inference. Unsupported providers stay explicit metadata-only entries until billing, quota, capability and permission controls are verified.

Before switching directors, run `<cli> handoff --contract contracts/<task>.json --attempt .factory/runs/assignment-<id>.json --next-action "concrete next check"`. Boot the same Brain, inspect hashes/partial work and reconcile the first unchecked acceptance on takeover. Expired quota becomes waiting/reset state; a replacement must meet the same risk/quality floor and verified account gates. Never blindly replay an interrupted write. Windows stale native controller locks are recovered only after proving owner and recorded workers absent; denied inspection keeps the lock.

After a real emulator/build/browser capture, register it using `<cli> artifact --path <project-relative-image> --source "capture tool/run" --task PB-NNN`. The panel serves only listed images whose byte hashes still match. Inspect the image and record build/source/device provenance separately: declared manifest provenance is not proof of a successful emulator build. Phone connection/pairing is deferred; reuse the user's existing remote console without exposing an unauthenticated listener.

Work in the selected application's own directory and Git repository. This skill supplies reusable tools; the tool-development repository is never the application's task store. Existing projects stay where they are. New products normally live beside other projects (for this user, D:/repositories/<app>), not inside store-otomaston. Never move an existing project to adopt the skill.

## Shared tools (optional OpenCode route)

Resolve `<skill>` to the directory containing this SKILL.md. `<cli>` below means `python "<skill>/runtime/tool/factory.py"`. Always run it **from the selected project root**. Installed resources are separate from current working directory; no store-otomaston checkout is required. The runtime's capability registry is measured evidence, not a permanent guarantee of free availability.

Global shell entry point: `store-automation` adopts the current project, executes and saves fresh discovery, then automatically starts an eligible official coordinator (currently Codex with verified shared quota). Unknown/depleted quota blocks inference; `open` opens the native OpenCode TUI after discovery without an automatic task. `store-automation start --host codex "goal"` starts official Codex instead. Inside an existing Codex conversation use `$store-automation` directly; do not launch a second supervisor. `store-automation adopt` performs local map/init/boot without inference; absent Brain gets a DRAFT target, preserved existing files, and no copied tasks.

Use the selected polished native console with an identifiable director and a pane for every actual agent; this user now authorizes Windows Terminal. Follow [live agents](references/live-agents.md). Codex sidebar attachment is a separate host capability; verify it before claiming it. `activity` shows durable execution state and measured usage. Other hosts use their native agent interfaces; do not fabricate an OpenCode session for them. `providers --scan --output .factory/runs/<unique-inventory>.json` refreshes official public help/auth/models/quota and OpenCode/OpenRouter catalogue evidence without credential reads; `--local-only` skips remote catalogue discovery. Installation/listing alone proves no access. Other detected official clients use their documented controls; the wrapper does not implement every provider adapter.

User communication follows their selected language (Turkish here); technical task contracts may remain English. Use `--language tr|en` on start/run/activity/sessions. Human status is default for live/activity output, with roles Yönetici / Uygulayıcı / İnceleyen; `--json` preserves structural machine output. Provider conversations are instructed to use the language, never presented as automatically translated. Process completion, agent verdict and final acceptance remain separate.

- `<cli> open`: open the native OpenCode coordinator TUI for the three responsibilities in the current project. `/factory-start <idea>`, `/factory-resume`, `/factory-audit` are provided in that session. Project/global OpenCode config files are not rewritten.
- `<cli> brain boot`, `<cli> brain new . "task title"`: canonical local task state. Genesis uses the Project Brain skill directly.
- Copy `runtime/contracts/delegation-smoke.json` as a **format example**, replace the old PB ID/persona/scope/evidence with the actual project task, then `<cli> contract contracts/<task>.json`. Write scopes are project-relative app source paths.
- New dispatch contracts require `delegation` with `provider`, `model`, `effort`, `reason`, `context_budget_chars`, `output_budget_tokens`, `checkpoint`, and `report_fields: [task, role, provider, model, effort, state, changed_files, evidence, usage, blockers, next_action]`. Minimally migrate an older contract before new dispatch; preserve historical evidence. See [task personas](references/task-personas.md).
- `<cli> route --contract contracts/<task>.json --inventory .factory/runs/inventory.json --complexity SIMPLE|STANDARD|COMPLEX|SPECIALIZED`: use inventory no older than five minutes, the shared 10% reserve and the quality floor. `CANDIDATES_REQUIRE_GATES` means candidates still need access/billing/permission gates.
- `<cli> native --contract contracts/<task>.json --prompt-file contracts/<task>.txt --inventory .factory/runs/inventory.json --complexity STANDARD --surface windows-terminal --output .factory/runs/<unique>.json`: current external Windows Terminal alternative opens an actual read-only Antigravity TUI after fresh quota and specific-model tool-free access checks. Native write dispatch is blocked until scoped permissions are verified; use the available scoped host worker or a read-only patch proposal. Special capabilities require separate evidence. Final JSON reports appear in the actual terminal and still await supervisor verification.
- `<cli> usage --record .factory/runs/<attempt>.json --expected .factory/runs/<expected-attempts>.json`: repeat `--record` for coordinator, children and retries; only authoritative counters count and missing manifest attempts make totals incomplete.
- `<cli> run --provider <verified-route> --contract contracts/<task>.json --prompt-file contracts/<task>.txt --output .factory/runs/<unique>.json`: native OpenCode worker scope or official Codex read-only handoff. Codex dispatch refreshes native metadata and shared quota immediately, selects contract model/effort or risk-sufficient defaults, and returns measured usage; incomplete reports are UNVERIFIED. First-pass implementation and fresh review are separate sessions; supervisor runs the checks.
- `<cli> check --contract contracts/<task>.json --worker-session <real-id> --output .factory/runs/<unique-check>.json`: Flutter format/fatal analysis/tests and, when contracted, Android APK build. Do not use the factory-source test profile for app verification.
- `<cli> gate --contract contracts/<task>.json --evidence .factory/runs/<check>.json --review .factory/runs/<review>.json`: exact source/log/artifact/contract/native-review checks. Other hosts must honestly record their own reviewer provenance rather than fabricate an OpenCode session.
- `<cli> sources --check-updates`: inspect configured external starter/core revision, dirty state and upstream HEAD once per session when network is available; never blindly pull or upgrade an existing app. Keep sources outside the skill and select a compatible immutable ref per app.
- `<cli> bootstrap D:/repositories/<new-app> --name "App" --package com.example.app --platform windows --ads no --pro no`: new explicit destination only; existing paths refused. Repeat required `--platform` for windows/web/android/ios. Uses configured external napp starter/core, strips inherited Brain, initializes new project Brain and runs checks with a primary build for the selected platform. Continue work from the new root; no central app registry. A failed generation leaves files for diagnosis, never overwrite-retry.

## Product and release decisions

Before generation or feature activation complete the [product intake and lifecycle gates](references/lifecycle.md#product-intake-and-stages). Ask every unresolved required choice; do not infer Android/iOS, ads, payment, cloud or a template license from the host OS. Explicit inclusions/exclusions override template defaults. Existing confirmed choices persist; Windows-only without ads/store is valid. Reuse the external napp template/core and its selected theme where applicable, recording compatible immutable refs. For backend selection read `runtime/docs/services.md` and verify current official quotas/terms; the factory installation roadmap is not an application lifecycle. UI work needs real accessibility/device/screenshot evidence; source-only review cannot prove visual acceptance.

No paid AI APIs, token transfers or automatic billing. Signing, account changes and production use existing app-specific authorization; do not ask again for an already authorized exact action. For release preparation read [publishing](references/publishing.md) and `runtime/.opencode/skills/factory-release/SKILL.md`; existing `D:/AppPublishing/README.md` stays the publishing source of truth. `release-preflight <app-root> --app-id <slug> --platform android --locale tr-TR --locale en-US` checks public local inputs without credential reads or uploads. Live receipt/store and iOS/Xcode limits stay in the affected project's Brain; never claim them passed from local Android evidence.

For iOS build/simulator screenshots and current Apple/Google release gates read [free-only iOS evidence](references/ios-ci.md). Use the supplied public standard-runner workflow only for deliberately public source and synthetic screenshots; private quota, artifact storage and signed store release are separate. `runtime/tool/ios-evidence.py` validates a PNG from native GitHub logs; inspect it and bind provenance to the actual source/run. Before each release refresh authoritative policy/SDK/privacy requirements against app behavior. Requested recurring updates follow [maintenance](references/lifecycle.md); never blindly bump dependencies or claim an unverified production upload.
