# Store Automation

## Single entry and mandatory preflight

Invoke only `$store-automation` or its host skill menu. Load Project Brain internally; the user never needs a second invocation. Brain owns project memory and acceptance; this skill owns economical, quality-preserving model routing and supervised execution. Every invocation follows this sequence **before investigating or implementing the reported problem**:

1. Select the actual application directory and run the available `project-brain` skill's boot there. On this host its canonical source is `C:/Users/rubicon/.skills-manager/skills/project-brain/SKILL.md`. Follow boot, intake and existing constraints; missing dependency is a blocker. For a new project follow Genesis, preserving source and user files. Its target stays DRAFT until the actual user goal is recorded and confirmed.
2. Run `<cli> providers --catalogue`. It creates `.factory/model-catalogue.json` by discovery only when absent; otherwise it reuses that project's catalogue and refreshes supported live account/auth/quota fields. Existing catalogue age, session restart, checkpoint or task completion never triggers full discovery. Run `<cli> providers --scan` only when the user explicitly requests a system/model rescan. An invalid catalogue fails closed: report the repair/rescan instruction; never silently discard it or use it as authority.
3. Inspect catalogue model IDs, supported effort, assessed capability/strength, account mode and remaining shared quota. Refresh native coordinator account limits too when the host exposes them. Separate durable model metadata from fresh account observations. Unsupported or unknown account/permission/capability adapters remain blocked; installation, login, catalogue listing and an ACK do not prove task access.
4. Classify task risk and required capability, then select the least sufficient verified model/effort from the catalogue. Include the director's own models in the comparison. Deterministic checks use tools without inference. Small diffs involving security, persistence or architecture retain the strong quality floor. A weaker director assigns that slice to a stronger specialist. An existing conversation cannot silently change its active model: report whether it stays director, delegates to a cheaper worker, or requires an explicit native handoff. No redundant orchestration model.
5. Prepare the task-specific [persona and bounded contract](references/task-personas.md), inspect the relevant Brain slice and exact source scope. Before each worker/reviewer starts, the director tells the user its task, role, provider, exact model, effort, selection reason/quality floor, context/output budget and current quota state. Report blocked starts, completion and reassignment in the user's language (Turkish here). Do not open a custom browser console, sidebar, terminal panes or agent UI.
6. Dispatch one bounded implementation task through an eligible scoped route, collect its public report, inspect its diff and run the contract's machine checks. Obtain a fresh independent review using a risk-sufficient model. The director alone reconciles Brain and accepts after both checks and review pass. Process completion and a worker verdict are separate from acceptance.

Read [CLI routing](references/cli-routing.md) for catalogue/account gates and [agent reporting and recovery](references/live-agents.md) for failures, intervention and takeover. If execution or independent review is unavailable, save the checkpoint and mark the gate UNVERIFIED; do not substitute silent director implementation or self-review.

## Project boundaries

Work in the selected application's own directory and Git repository. Existing projects stay where they are; new products normally live beside them, e.g. `D:/repositories/<app>`, never inside the tool repository. Application tasks/checkpoints belong to that application's `.project-brain/`, contracts to `contracts/`, and private execution evidence to ignored `.factory/runs/`. Project-local PB IDs are independent. Keep no application progress, personal accounts, credentials or raw task logs in this installed skill.

Preserve unknown/user edits, napp, Fastlane and existing Brain components. Workers cannot write Brain or tool policies. One application writer at a time; parallel work requires disjoint isolated scopes. Reuse existing helpers, stdlib/native features and installed dependencies; smallest correct diff, one runnable check for nontrivial logic. For adoption and recurring maintenance follow [lifecycle](references/lifecycle.md). `adopt --rebaseline` previews and `--apply` reversibly archives the old plan; ordinary resume never resets history.

## Account and quality boundaries

Existing user authorization covers installed official subscriptions, automatic task-appropriate routing and missing official CLI installation; login remains user-owned. Record durable authorization in the selected project's Brain constraints and ask only a missing decision that blocks work. No paid AI API, credential reads/transfers, billing/signing changes or store production in this factory. Subscription access never implies API access. Qwen is excluded. Claude/Opus stays excluded until the user confirms availability and fresh specific-model access is verified. Shared account quota never proves another model's entitlement.

Choose persona from the task and model/effort separately from verified capabilities. Do not infer quality from a name, popularity or quota abundance. Unknown models remain UNASSESSED. A bounded authorized calibration can supply evidence only after billing/quota/permission gates; it cannot certify production acceptance. At <=10% remaining in any shared window, start no new job in that bucket. Unknown quota blocks inference. Count shared buckets once; usage for director, children and retries is complete only with authoritative counters and complete attempt coverage. Unknown usage remains null.

## Runtime and commands

Resolve `<skill>` to this SKILL.md's directory and `<cli>` to `python "<skill>/runtime/tool/factory.py"`. Run from the selected project root; installed resources remain independent of cwd. Native controls are optional provider-specific tools, never a visibility requirement. The director's conversational updates are the user-facing agent reporting surface.

- `providers --catalogue`: reuse/create the project catalogue and refresh supported live account fields. `providers --scan`: explicit full discovery/rescan; `--local-only` omits optional remote free-model listings. No credential reads or automatic billing.
- `start --host auto|codex "goal"`: adopt/boot, perform catalogue preflight and start an eligible native coordinator. Inside an existing conversation use this skill directly, retaining that director. `adopt` initializes only local Brain; `open` opens the optional native OpenCode TUI.
- `brain boot` / `brain new . "task title"`: canonical local project state. Use the Project Brain skill for Genesis.
- Copy `runtime/contracts/delegation-smoke.json` only as a format example; replace its PB ID, persona, scope and evidence. `contract contracts/<task>.json` validates it. New dispatch requires complete `delegation` and report fields described in [task personas](references/task-personas.md); preserve historic evidence when migrating an old contract.
- `route --contract contracts/<task>.json --inventory .factory/runs/<inventory>.json --complexity SIMPLE|STANDARD|COMPLEX|SPECIALIZED`: risk-sufficient candidates with fresh account observations and the shared reserve. `CANDIDATES_REQUIRE_GATES` is not access proof.
- `run --provider <verified-route> --contract contracts/<task>.json --prompt-file contracts/<task>.txt --output .factory/runs/<unique>.json`: bounded native execution. Official Codex snapshot handoff is read-only; use the validated app wrapper or a director-applied reviewed patch for source writes. Unsupported permission adapters cannot dispatch writes.
- `check --contract contracts/<task>.json --worker-session <real-id> --output .factory/runs/<unique-check>.json`: contracted format/analyze/tests/build. App verification uses the app profile.
- `gate --contract contracts/<task>.json --evidence .factory/runs/<check>.json --review .factory/runs/<review>.json`: exact evidence/source/contract checks. Its OpenCode review validation cannot certify another host's reviewer; retain honest native provenance for that host.
- `handoff --contract contracts/<task>.json --attempt .factory/runs/assignment-<id>.json --next-action "concrete next check"`: durable recovery before changing director/worker. `activity` shows sanitized project attempt evidence; `usage --record <attempt> --expected <manifest>` checks coverage for all attempts.
- `sources --check-updates`: inspect external starter/core once per session when available; never blindly pull/upgrade. Pin compatible immutable refs. `bootstrap <new-path> --name "App" --package com.example.app --platform <chosen> --ads no --pro no` requires a new explicit destination and chosen platform(s); failed generation leaves files for diagnosis. Continue in the new project root.

## Product and release

For complete frontend/backend delivery, localized marketing assets, distribution and postlaunch care follow [product delivery](references/product-delivery.md). Before major implementation and after consequential integration changes use the [architecture critique and fresh review protocol](references/architecture-review.md); record the smallest evidence-backed solution and resolve release blockers before submission.

Before generation or feature activation complete [product intake and lifecycle gates](references/lifecycle.md#product-intake-and-stages). Ask unresolved required product choices; never infer platforms, ads, payments, cloud or license from the host OS. Confirmed choices persist. Reuse compatible external napp starter/core and the selected theme. For backend decisions read `runtime/docs/services.md` and verify current official quotas/terms. Interface acceptance requires real accessibility/device/screenshot evidence; source review alone is insufficient.

For release preparation read [publishing](references/publishing.md) and `runtime/.opencode/skills/factory-release/SKILL.md`. `D:/AppPublishing/README.md` remains the publishing source of truth. `release-preflight <app-root> --app-id <slug> --platform android --locale tr-TR --locale en-US` reads public local inputs without credentials or uploads. Store/receipt/iOS account limits stay in the affected project's Brain. For iOS simulator/build evidence read [free-only iOS evidence](references/ios-ci.md); public standard-runner workflows require deliberately public source and synthetic screenshots. Inspect resulting artifacts and bind source/build/device provenance. Refresh official policy/SDK/privacy requirements before release; never claim an unverified upload or production acceptance.
