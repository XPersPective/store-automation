# Subscription CLI routing

Verified locally 2026-10-11; recheck before dispatch. CLI presence/auth/listing/inference are separate evidence levels. A subscription authorization does not verify entitlement, remaining quota or free overage behavior. Keep personal account names/tokens out of task logs.

## Routing rule

| Task | First choice | Upgrade trigger |
|---|---|---|
| Format, hash, search, fixed validation/build | Existing script/stdlib/tool; no inference | Human judgment actually needed |
| Small bounded edit or summary | Approved lightweight model, low effort, minimal source slice | Concrete failed acceptance after correcting context |
| Normal feature/debugging | Approved standard coding model, task persona | Cross-module ambiguity or unresolved failure |
| Architecture/security/difficult diagnosis | Strong approved model with relevant persona | Use only for the complex slice |
| Independent review | Fresh session capable of checking the task risk | Never self-certify implementation or unavailable visual proof |

Use the existing assistant for quick local actions; no extra orchestrator hop. Budget the context to contract + affected callers, not entire histories. Before upgrading record the failed acceptance and reason in the project task. On quota/auth/timeouts checkpoint and check the real diff; do not restart partial writes blindly. Do not escalate every failure to a more expensive model. Respect project preferences; an explicit per-task model request wins. Current host model cannot necessarily be changed mid-turn: reduce unnecessary calls or dispatch an approved lighter CLI instead of pretending it changed.

## Catalogue and handoff cadence

On intake and after access/quota changes, refresh installed official CLI metadata, then build the project-local catalogue from observed provider/model IDs and documented effort controls. Keep installation, login, plan mode/overage, model list, model-specific inference, task/tools capability, quota windows/reset and capture time separate. Classify task suitability as assessed lightweight/standard/strong/specialized; it is not a measured price or entitlement. Codex lightweight Luna can be chosen only when the official CLI actually offers it with approved account access. A model available in this host's agent tool is not automatically available through Codex CLI. No speculative cost ranking or API access from subscription login; paid API remains outside current authorization. Newly found CLIs require official documentation and an actual adapter/capability check, not borrowed credentials.

At each completion, failure, intervention and before switching providers, record public report, actual diff/unchecked acceptance, commands/artifacts, pending process/session and next action in the single project Brain; keep per-attempt usage in ignored execution evidence. Refresh account limits before each dispatch and after a long task; summarize coordinator, all children/retries and inclusive counters correctly. If native quota reporting is unavailable record null and the official manual status action; do not invent a remaining budget. Historical catalogues cannot authorize current work.

Before the coordinator reaches its reserve, finish the checkpoint for all active tasks/agents, persist continuation contracts and report that execution waits for reset. Do not spend the final reserve starting another job or transferring the director implicitly. A depleted worker first stops safely and saves its diff/handoff; only then can an approved route with fresh independent quota and equivalent capabilities take the first unchecked acceptance. Unknown quota is not zero or permission to dispatch. `runtime/tool/subscriptions.py:reserve_decision` tests these decisions; it consumes verified handoff/equivalence facts, not an automatic multi-provider transport. One writer per application, no concurrent replacement or blind replay.

## Automatic discovery cycle

This is mandatory skill behavior, not a user-maintained provider list:
1. After project Brain boot/Genesis, run `providers --scan --output .factory/runs/<unique-inventory>.json` and inspect installed official executables/host apps plus available provider tools. The wrapper recognizes known client names; supplement it with PATH/installed app/package metadata and user-configured routes without opening credential/config secrets. New tools require official identity/help verification; never execute arbitrary discovered binaries as probes.
2. For every detected client automatically investigate its current official model listing, effort controls, account/plan and native status/quota actions. Use read-only supported metadata commands. Where no supported machine interface exists, expose UNKNOWN plus the exact official action and create a task for the adapter; never omit the client. Capture timestamps and evidence, keep account identifiers/secrets out.
3. Refresh OpenCode and optional OpenRouter public free models; disappearance/new entries trigger reassessment, not automatic trust. Public zero-price catalogue entries have no account quota or tool/coding quality proof. Other detected API routes are included from public endpoint/model/price docs and user-approved metadata; retain native credential references only, never request keys in chat or store them in Brain. No paid inference or new billing activation follows from discovery.
4. Classify each observed model for simple/standard/complex/specialized tasks from relevant documented capabilities and bounded authorized evidence. Record rationale, context/tool/vision limits, supported effort and independent review needs. UNASSESSED remains ineligible until evaluated; model names/popularity do not prove quality. Compare eligible routes across providers, including stronger workers than the director; never hardwire AGY as the only policy choice. The bundled `route` command compares AGY and official Codex model/effort/shared-quota candidates. Codex app-server model/list and account/rateLimits/read are bounded metadata operations; candidate status still requires actual task access. Other native clients remain in the dynamic catalogue with honest per-interface limits.
5. Query the coordinator's native usage tool (Codex `get_usage_limits` on this host) and all active provider quota windows before a new job, after long work and at completion/failure/intervention. Poll available native status during long jobs at the provider's documented safe cadence; no model inference just to ask usage. Context/output budgets are separate from account quotas. Track all attempts/retries, record unknown fields as null, write summaries and handoffs at checkpoints.
6. At reserve save partial diffs, exact unchecked criteria, native sessions/process ownership, pending reports and continuation before waiting/switching. If live observation or automatic relay is unsupported, retain the exact blocker and explicit supervisor collection rather than asserting continuous monitoring. Resume rebuilds the catalogue and checks reality again; old model/quota records do not authorize dispatch.
