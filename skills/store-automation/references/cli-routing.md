# Catalogue, account gates and routing

## Mandatory catalogue preflight

After selected-project Brain boot, run `providers --catalogue` before problem investigation or task execution. The durable project catalogue is `.factory/model-catalogue.json`. An absent catalogue triggers one bounded official discovery and saves the result. An existing valid catalogue is reused across invocations, sessions, checkpoints and takeovers. Full discovery runs again only for the user's explicit system/model rescan (`providers --scan`); a new client, metadata age or access error alone is not permission to rescan. A corrupt, linked or invalid catalogue fails closed with the exact repair/rescan action; never silently overwrite it, skip preflight or infer permissions from it.

Catalogue metadata and account observations have different lifetimes. Cache observed provider/model IDs, documented effort controls, source/capture provenance and assessed capability/strength. Before each inference refresh eligible account authentication, approved billing mode, shared quota/reset and task permission/access gates through supported native controls. Fresh account observations do not rebuild model lists or rediscover clients. The route's account observation must be no older than five minutes and is refreshed immediately before dispatch; a catalogue's age alone does not invalidate its model metadata. A cached model removed or denied by the provider becomes unavailable for that attempt; do not silently replace the catalogue or auto-pay.

Public listings prove neither account access nor coding/tool/vision suitability. Unknown adapters, account fields or capabilities remain explicit gaps and block affected inference. A new explicit scan verifies official client identity/help and public metadata, never executes arbitrary discovered binaries or opens credential/config secrets. Public zero-price entries are metadata only. No automatic installation, login, account switching, billing activation or paid API follows from discovery. Existing authorization for missing official CLI installation persists; login remains user-owned.

## Quality with economical execution

| Task | Least sufficient choice | Escalation evidence |
|---|---|---|
| Search, format, hashes, fixed validation/build | Existing script/stdlib/native tool; no inference | Actual judgment required |
| Bounded low-risk edit or summary | Verified lightweight model, low effort | Failed acceptance after correcting context |
| Normal implementation/debugging | Verified standard coding model, sufficient medium/high effort | Cross-module ambiguity or unresolved concrete failure |
| Architecture/security/persistence/difficult diagnosis | Strong task-qualified model, high effort | Stronger specialist for the unresolved slice |
| Independent review | Fresh session meeting the task's risk floor | Missing review capability or machine/visual evidence blocks acceptance |

Risk overrides diff size. Include the current director's own catalogue models in every selection comparison. Keep the current conversation as director when it can coordinate; delegate substantive execution to the cheapest sufficient verified specialist. If its competence is below the task floor, assign the complex slice to a stronger specialist. Do not add an orchestration hop or pretend the active host model changed. An explicit per-task model preference remains subject to access, quality and quota gates.

Choose task persona and model separately. Known assessed strength is a suitability judgment with evidence, not measured price or entitlement; UNASSESSED models cannot dispatch. A name, popularity or plentiful quota cannot establish suitability. The runtime's supported candidate adapters do not imply support for every listed provider. An authorized bounded non-mutating model-access/calibration probe requires approved billing, quota and permission controls; its success is not implementation, tool capability or acceptance proof. Unsupported providers stay blocked without borrowed credentials or fabricated flags.

Before dispatch disclose task, role, provider/model/effort, reason/quality floor, context/output budgets and current quota state to the user. Include only contract, relevant Brain slice, affected source/callers and verification commands. Do not send entire histories or repeat unchanged context. Declared output budgets are soft unless the native provider enforces them; measured overruns remain visible. Record failed acceptance before upgrading and upgrade only the necessary slice. A timeout/auth/permission failure needs diagnosis and checkpointing, not automatic stronger-model retries.

## Account and reserve rules

Use only approved official subscription/free routes with task-specific fresh evidence. Subscription login never proves API access. Qwen is excluded; Claude/Opus is unavailable until user availability and fresh specific-model entitlement both exist. Shared Antigravity Claude/GPT quota does not prove entitlement. Do not bypass provider client restrictions. Credentials, hidden reasoning and private account identities stay out of structural evidence.

At <=10% remaining in any shared account window, start no new job in that bucket. Unknown quota also blocks inference. Finish a safe checkpoint before reserve exhaustion; await reset or use an equally qualified approved route after fresh independent account checks. No implicit director transfer. A replacement starts only after the original writer is proved stopped and its partial diff/unchecked criteria are reconciled.

Track director, every child and retry in the attempt manifest; `usage --record <attempt> --expected <manifest>` must cover all attempts before totals are called complete. Unknown counters stay null. Inclusive/cumulative counters are counted once, shared quota buckets once; fractions are not token counts. Actual measured cost does not establish subscription billing or remaining credit. Refresh supported account limits after long work; this is not a discovery request.

## Recovery and evidence

On completion, failure, intervention or provider change preserve actual report, diff/hash, unchecked acceptance, checks/artifacts, process/session ownership, usage and next action in project-owned records. Brain stores the concise current checkpoint; private attempt data stays in ignored `.factory/runs/`. Do not rewrite historical evidence or accumulate release logs in this installed skill.

Resume uses the same cached catalogue, then refreshes account fields and inspects real partial work before continuing the first unchecked criterion. See [agent reporting and recovery](live-agents.md). Stale quota cannot authorize dispatch, old success cannot prove current access, and unavailable independent review cannot be replaced with self-review.
