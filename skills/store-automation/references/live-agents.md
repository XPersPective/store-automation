# Live agents and intervention

Use a polished installed native console, not a bare Windows console or a new terminal implementation. This user's latest request authorizes Windows Terminal. Keep the director identifiable and each actual agent visible with its role/name, task, provider/model/effort, progress, quota and measured usage (unknown stays unknown). Three responsibilities do not cap team size. Choose a readable split layout for actual team size; use native host surfaces when supported.

The OpenCode watcher opens an owned Windows Terminal tab, activity above and director left, then distributes all observed worker sessions across the worker area with persistent safe titles. Fixed pane targeting tolerates focus changes; closing/reordering panes requires rebuilding the view. Structural layout tests do not prove native visual quality. Verify real rendered panes and user questions/interrupt/resume before accepting the console gate. Logs do not prove conversation or application visual acceptance.

`native --surface windows-terminal --contract <contract> --prompt-file <prompt> --inventory <inventory> --complexity STANDARD --output <record>` opens an actual Antigravity TUI after quota and specific-model access checks. It currently opens an individual tab, not an automatically unified multi-provider team. Write contracts and unverified specialized capabilities remain refused. Final reports appear in the terminal; the supervisor must capture/check them. Automatic cross-provider conversation/intervention relay is not implemented. Do not represent a reporting prompt as that transport.

For user intervention pause the affected writer through supported native controls, record the changed direction/checkpoint, notify the director, and resume only after the contract is reconciled. Every agent reports completion/blocker and evidence to the director; no acceptance while a report is missing. If the native tool lacks automatic reporting, require explicit supervisor collection and expose that limitation. Codex right-sidebar attachment is a separate optional host gate: observed real terminal ID plus supported `open_in_codex` binding and verified visibility; queued requests prove no attachment. Never invent session IDs. Denied/empty/timed-out work stays UNVERIFIED and must not be blindly replayed.

For a task dispatched through the installed wrapper, add `--visible` to `run`. On Windows this starts a task-scoped OpenCode loopback server using the **exact validated contract permissions**, a process-only random local password and Windows Terminal. Actual native sessions appear in split panes as their IDs are observed. A public activity pane shows role/provider/model, tool states and reported token counters. Completion stops only the owned server; session history and sanitized lifecycle evidence stay in the selected project's `.factory/runs/`.

The supervisor uses `--visible` for OpenCode task dispatch when the selected console is Windows Terminal. Read-only direct interactive workers stay read-only. Never reuse a server with different permission config; never bypass the wrapper's contract/single-project dispatch lock to automate another writer. The user may inspect/intervene in a displayed native session. Let the native client handle active-session interruption/queueing; do not launch a second implementation to answer an intervention.

`store-automation activity` displays recent project-owned lifecycle records after a run/crash, including measured usage. FINISHED records process exit; task acceptance is the separate task_result and evidence gate, never inferred from exit zero. Nested-agent usage is not necessarily included in the supervisor stream; counters are not an account-wide total. Unknown input/output/cache/reasoning/cost/quota fields remain null. Measured cost is a provider report, not subscription billing or remaining credit proof. Structural logs exclude prompts, source contents, tool inputs/output and hidden reasoning. Original run evidence may contain source/review output; keep `.factory/` ignored and do not publish it.

Advanced native controls: `sessions start|status|watch|attach|stop`. Manual server start requires the same private process environment `OPENCODE_SERVER_PASSWORD` and loaded native config; the wrapper supplies config. For a task server use `--contract contracts/<task>.json`. `sessions attach --session ses_<actual-id> --pane` verifies that the session belongs to the current project and permissions match. No plaintext server password is stored. Manual controls from a different process need that environment; the automatic `run --visible` path handles it internally.

Codex/Claude/Gemini native sessions have their own clients and IDs. Use current official attach/resume/queue controls in their native host; do not treat them as OpenCode sessions or claim a universal interactive adapter. A Codex wrapper snapshot handoff streams structural activity but cannot use OpenCode panes; the Codex host's native agent interface is the intervention surface. Preserve a provider/project-specific handoff and inspect partial writes before changing models.

Windows Terminal launches executable argument vectors, never generated shell strings. See [Microsoft's terminal argument reference](https://learn.microsoft.com/en-us/windows/terminal/command-line-arguments). Native terminal visibility does not prove inference access, successful implementation or visual application acceptance.

Human output defaults to Turkish: Yönetici, Uygulayıcı, İnceleyen. Use `activity --language en`, `sessions watch --language en`, or `run --language en` for English; `--json` requests structural machine output. Public summaries show actual session/tool/model status and measured counters, never conversation/tool body or hidden reasoning. A process success and an agent PASS remain separate from machine verification plus independent acceptance. Saved server language governs later attach/watch when no language override is supplied.
